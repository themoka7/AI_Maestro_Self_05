# MediaWatch — 보도 공정성 & 보도자료 의존도 분석기

특정 공적 사안(지자체 주최 대형 행사, 지방의회 이슈 등)에 대한 **하루치 보도**를 모아,
지자체 공식 보도자료와 대조해 **복제율**과 **보도 프레이밍**을 정량화하는 대시보드입니다.

주관적 도덕 판단이 아니라 세 가지 관측 가능한 지표만 다룹니다.

1. **보도자료 복제율** — 공식 보도자료와의 형태소 단위 유사도
2. **보도 프레이밍** — 감시(Watchdog) / 홍보(Cheerleader) / 중립(Neutral)
3. **언론사 자율성 점수** — 위 둘을 매체 단위로 집계한 0~100 점수

---

## 시작하기 전에 — 이 프로젝트에서 가장 중요한 두 가지

**하나. 네이버 검색 API는 본문을 주지 않습니다.**
제목과 200자 내외 요약만 옵니다. 복제율은 본문 없이 계산할 수 없으므로 `originallink` 를
직접 받아와 본문을 추출합니다(`pipeline/extract_body.py`). 여기서 robots.txt 차단·추출
실패가 발생하며, **이 누락은 매체별로 균등하지 않습니다.** 수집률을 항상 함께 보고하세요.

**둘. 검증 셋 없이 공개하면 안 됩니다.**
언론사를 실명으로 줄 세우는 화면입니다. LLM 분류가 사람 판단과 얼마나 일치하는지
수치로 대지 못하면 그 숫자는 내부 검토용입니다. `pipeline/evaluate.py` 로 100건 정도를
직접 라벨링하고 Cohen's κ 를 확인하세요. **κ 0.6 미만이면 대외 공개 금지**입니다.

## 파이프라인 단계

| 단계 | 스크립트 | 하는 일 |
|---|---|---|
| 1 | `collect_pr.py` | 지자체 보도자료 수집 (게시판 스크래핑 또는 JSON 임포트) |
| 2 | `collect_news.py` | 네이버 검색 API로 대상 날짜 기사 목록 수집 |
| 3 | `extract_body.py` | 원문 본문 추출 (robots.txt 준수, 도메인별 속도 제한) |
| 4 | `dedup.py` | 통신사 전재 클러스터링 |
| 5 | `match.py` | 기사↔보도자료 매칭, 문서·문장 단위 복제 지표 |
| 6 | `classify.py` | Claude Batch API 로 프레이밍 분류 |
| 7 | `export.py` | 대시보드용 JSON 산출 |
| — | `evaluate.py` | 검증 셋 라벨링·정확도 리포트 (공개 전 필수) |

각 단계는 **멱등**합니다. 같은 날 여러 번 돌려도 기사가 중복으로 쌓이지 않고,
이미 본문을 받아온 기사는 다시 받지 않으며, 이미 분류된 기사는 다시 분류하지 않습니다.

## 방법론

### 복제율

한국어에서 `rapidfuzz.token_set_ratio` 같은 어절 단위 비교는 조사·어미 때문에
"여수시**는** / 여수시**가** / 여수시**의**" 가 전부 다른 토큰이 되어 복제율을 과소평가합니다.
그래서 **Kiwi 형태소 분석 후 내용 형태소만 남겨** 비교합니다.

```
doc_score = 0.6 × Jaccard(형태소 3-gram) + 0.4 × LCS비율
```

여기에 **문장 단위 정렬**을 함께 계산합니다. 기사 문장마다 가장 비슷한 보도자료 문장을
찾아 일치도를 기록하며, 이게 있어야 UI 의 좌우 대조 하이라이트를 그릴 수 있습니다.
문서 점수 하나만 있으면 "어디를 베꼈는지"를 보여줄 수 없습니다.

최종 복제 판정은 `doc_score` 와 `문장 복제 비율` 중 **큰 쪽**이 임계값(기본 0.70) 이상일 때입니다.
기사가 보도자료의 일부만 그대로 옮긴 경우 문서 점수는 낮게 나오기 때문입니다.

### 자율성 점수

```
raw   = 0.6 × 감시비율 + 0.4 × 중립비율 − 0.5 × 복제비율      값역 [−0.5, 0.6]
점수  = (raw + 0.5) / 1.1 × 100                              → 0 ~ 100
```

두 가지 보정을 넣었습니다.

- **베이지안 shrinkage** — 각 비율을 전체 평균 쪽으로 당깁니다(사전 표본 10).
  이게 없으면 기사 2건 중 1건이 감시 보도인 매체가 비율 50%로 전국지를 앞지릅니다.
- **최소 표본** — 기사 5건 미만은 순위에서 제외하고 별도 표기합니다.

### 집계 기준

언론사 점수는 **그 매체가 실제로 내보낸 모든 기사** 기준입니다.
통신사 기사를 그대로 받아 싣는 것 자체가 이 지표가 측정하려는 행태이므로,
전재본을 빼고 세면 정작 의존도가 높은 매체가 집계에서 사라집니다.
전재 클러스터는 "이날 고유 기사가 몇 건이었나" 하는 이벤트 레벨 통계에만 씁니다.

### 분류

복제율을 분류 프롬프트에 **넣지 않습니다.** 복제율과 프레이밍을 독립 신호로 둬야
"복제율이 높아서 홍보로 분류됐다"는 순환논증을 피할 수 있습니다.

## 이 지표가 재지 않는 것

- 기사의 **사실성·품질·정치적 정당성** — 재지 않습니다. 취재 행위의 형태만 봅니다.
- 보도자료를 인용한 기사가 곧 잘못된 기사는 **아닙니다.** 단순 사실 고지(교통통제,
  운영시간)는 의도적으로 중립으로 분류됩니다.
- 분류는 언어모델이 수행하므로 **오분류가 존재합니다.** 개별 기사 판정은 원문과 대조하세요.
- 본문 수집 실패로 빠진 기사가 있으며, 그 누락은 매체별로 균등하지 않을 수 있습니다.

## 법적·윤리적 주의

- **저작권** — 기사 본문은 분석용으로만 DB에 보관합니다. `export.py` 는 기본값
  (`--excerpt-only`)으로 보도자료와 매칭된 문장만 내보냅니다. 복제를 지적하는 서비스가
  스스로 전문을 재공개하면 안 됩니다.
- **수집 예절** — robots.txt 를 확인하고, 도메인별 요청 간격을 두며, 식별 가능한
  User-Agent 를 씁니다.
- **명예훼손** — 언론사 실명 랭킹을 공개한다면 방법론·표본 수·검증 결과를 같은 화면에서
  함께 밝히세요. 대시보드의 "방법론과 한계" 섹션이 그 역할을 합니다.

## 설정

분석 대상 이벤트, 검색어, 보도자료 소스, 임계값은 전부 `config/event.yaml` 에 있습니다.
이 파일만 바꾸면 다른 이벤트·지역 이슈로 그대로 재사용됩니다.

언론사 도메인 매핑은 `pipeline/sources/outlets.py` 에 있고,
`config/outlets_override.csv` (`domain,name`) 로 얼마든지 덧붙일 수 있습니다.
매핑에 없는 도메인은 도메인 문자열 그대로 "미확인"으로 노출되며,
`collect_news.py` 실행 시 누락 도메인 상위 목록을 출력합니다.

## 색상 체계

프레이밍은 **발산형(diverging)** 스케일입니다.

```
감시(파랑) ←──── 중립(회색) ────→ 보도자료 의존(빨강)
```

복제율과 '홍보' 분류는 같은 구성개념(보도자료 의존)을 재므로 같은 색을 씁니다.
라이트·다크 모드 모두 CVD(색각 이상) 분리도 ΔE 8 이상, 대비 3:1 이상을 통과했으며,
색만으로 구분되지 않도록 모든 범례·배지에 기호(◆ ■ ▲)와 수치를 함께 둡니다.

- **대시보드** — Next.js 15 (App Router), TypeScript, Tailwind CSS, 인라인 SVG 차트

파이프라인이 JSON 을 떨구고 웹이 그걸 읽는 구조입니다. 네이티브 모듈(better-sqlite3)
빌드를 피하고, 나중에 DB 를 바꾸더라도 JSON 계약만 지키면 프런트를 건드릴 필요가 없습니다.
